## Codebase Patterns

### Concise Estimation Documentation
- **Where**: `README.md:87`
- **Pattern**: Public documentation keeps actor-aware estimation details in the existing tools/config/examples/how-it-works sections instead of adding a separate research appendix.
- **Example**: ``temporal_estimate` | Estimate task duration by category/complexity, with optional actor-aware software task details`

### Focused Estimator Test Harness
- **Where**: `tests/task-estimator.test.ts:8`
- **Pattern**: Estimator tests directly instantiate `TaskTimeEstimator` with a minimal complete `TemporalCognitionState` fixture and synthetic `TaskHistoryEntry` arrays.
- **Example**: `new TaskTimeEstimator(undefined, createState(taskHistory)).estimate('coding', 'simple', detail)`

### Validation Scripts Without Extra Tooling
- **Where**: `package.json:12`
- **Pattern**: Package validation scripts use the existing TypeScript compiler and Bun test runner, avoiding new dependencies while making Ralph validation commands available.
- **Example**: `"type-check": "tsc --noEmit", "test": "bun test"`

### Tool Estimation Detail Reuse
- **Where**: `src/tools/temporal-tools.ts:51`
- **Pattern**: Temporal tools share the same optional estimation-detail schema and call `buildSoftwareTaskDetail(params)` before invoking `TaskTimeEstimator.estimate(...)`.
- **Example**: `ctx.taskEstimator.estimate(params.category, params.complexity, buildSoftwareTaskDetail(params))`

### Estimator Baseline Precedence
- **Where**: `src/engines/task-estimator.ts:97`
- **Pattern**: `TaskTimeEstimator.getBaseline()` should check learned history first, then calibrated software details for coding tasks, then legacy category baselines.
- **Example**: `learned-history > calibrated-software > default-category`

### Tests Stay Outside Source Build
- **Where**: `tsconfig.json:14`
- **Pattern**: The TypeScript build includes `src/**/*`, so Bun tests that import `bun:test` should live under `tests/` unless Bun type declarations are added.
- **Example**: `tests/constants.test.ts`

### Estimation Constants Stay Centralized
- **Where**: `src/constants.ts:27`
- **Pattern**: Shared estimator constants use exported `Record<...>` tables keyed by existing domain literal types.
- **Example**: `Record<SoftwareTaskType, Record<ActorProfile, Record<TaskComplexity, number>>>`
